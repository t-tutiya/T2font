# Rinkaku

T2Font（`info.someiyoshino.t2font`）の上に足すグリフ表現。TrueType の輪郭を 2 次ベジエのセグメントのまま持ち、画素ごとに**最近傍のセグメントへの厳密な
符号付き距離**を求めて描く。符号付き距離の意味は T2Font の SDF と同じなので、エッジスタイル（面の縁のずらし・ぼかし・縁取りの幅・外縁のぼかし）は
SDF と同じ式のまま全値域で成り立ち、縁は表示サイズに依らず鋭い。

キーは**グリッド**: グリフを 1/indexEm em 角のグリッドに切り、texel ごとに「その texel の面積のどこかから見て最近傍になるセグメント」の集合をベイクで求めて
書く。シェーダは texel の集合（たいてい 1〜4 本）だけを評価する。符号は最近傍のセグメントの向き（内点は接線の右手の法線・端点は擬似法線）から決めるので、
巻き数を数える必要が無い。重なった輪郭はベイクで和集合輪郭に作り直す。

本書がこのパッケージの契約の正典（データの形式・ベイクの算法・ベイク仕様・バージョン）。T2Font の契約（頂点・テクスチャ・マテリアル・シェーダ・
エッジスタイル・ベイク仕様の読み方）は T2Font の README による。

## 2. 描ける効果とサポートする表示サイズ

- **描ける効果**: 全部（`GlyphEffects.All`）。符号付き距離を SDF と同じ意味（インク領域の内側が正・em）で持つので、T2Font のエッジスタイルの値をそのまま使える。
- **幾何**: 覆える範囲は、インク境界を `GlyphEdgeStyle.MaxOuterExtentEm`（0.15em）＋最小の表示サイズの AA の半分（0.5/14 em）だけ広げた矩形
  （`RinkakuEncoding.ExtentEm`）で、グリッドはこの範囲を覆う。quad は、ホストが渡す幅（T2Font の README §4.3）までこの矩形を狭めたもの
  ——狭い quad はインデックスの内側の部分だけを引く。サポートする最小の表示サイズは **14px**（SDF と同じ）。
- 縁取りの外角は真の距離の等値線（円弧）で、texel による丸まりは無い。
- 効果は値域の端の組（太らせ −0.03・0.04、面のぼかし 0.06、縁取り 0.08 と外縁のぼかし 0.06、細らせと縁取り、全部の最大）で、GPU で描いた面と全体の α を、
  ページから読み戻した距離から同じ式で求めた値と画素ごとに比べて確かめる（距離が正しければ効果も正しい。式は SDF と同じ）。D3D11 の NVIDIA GeForce
  RTX 5070 Ti と AMD Radeon Graphics（統合 GPU）で、M+ 1c・M+ 2p heavy・IPAex 明朝の 18 字（ワイドインデックスの「麤」を含む）×7 組を 192px で描き、食い違う
  画素は 0、差の最大は 0.005（8bit の 1〜2 段）だった。
- **描画の時間**は、同じ quad で画素あたり SDF の 5〜21 倍（§7）。字の多い本文には向かず、大きな字に向く。

## 3. データの形式

### 3.1 ページ

- テクスチャ 1 枚＝RGBA8・非圧縮・point・linear・ミップ無し・clamp（T2Font の `GlyphBakeContext.AddDataTexture` で作る）。**幅は常に 4096 texel**、
  高さは中身で決まり上限は `maxPageSize`（≤ 4096）。行 0 が下端。
- **線形の番地** `a = y × 4096 + x`（< 2^24 なので float で正確に持てる）。セグメントテーブルとレコードは線形の番地で引き、インデックスブロックは 2 次元で引く。
- 1 ページの上側にインデックスブロックを棚詰めし（高い順・同じ高さはグリフの順）、その下の行からセグメントテーブルを線形に並べる。上限を超えたら次のページ。

### 3.2 セグメントテーブル

グリフごとに連続した項目の列。**項目 1 つ＝texel 2 つ＝8 バイト**。セグメント i は項目 i の始点・制御点と、項目 i+1 の始点（＝セグメント i の終点）でできる。
輪郭ごとにセグメントの項目を並べ、**終端の項目**（輪郭の始点と、その擬似法線だけを持つ）で閉じる。

| バイト | 中身 |
|---|---|
| 0・1 | 始点の x（16bit・下位が先）＝`(x + 1) × 16384`。−1〜3em を 1/16384 em で持つ |
| 2・3 | 始点の y（同じ） |
| 4・5 下位 4bit | 制御点の始点からの差 dx（符号付き 12bit・2 の補数）＝`dx × 4096`。±0.5em を 1/4096 em で持つ |
| 5 上位 4bit・6 | 同じく dy（下位 4bit が 5 の上位、上位 8bit が 6） |
| 7 | 始点での**擬似法線**の角（`atan2` を 256 段・塗る側を向く）。最近傍が端点のときの符号にだけ使う |

- **塗る側は進行方向の右手**（和集合輪郭・§4.1）。内点が最近傍なら、接線 `B'(t)` の右手の法線 `(B'y, −B'x)` と `p − B(t)` の内積が正なら内側。
- **擬似法線**は頂点に入るセグメントと出るセグメントの、右手の単位法線の和（2 次元では角の二等分線＝角度で重み付けた擬似法線と同じ向き）。
- **直線は制御点の差を (0, 0) にして持つ**（直線の印・出力のバージョン 3）。シェーダはこの項目を三次方程式で解かず、正射影で測る（§3.5）。制御点が始点に
  重なる 2 次ベジエは始点から終点への線分そのもの（同じ点の集まり）なので、量子化で差が (0, 0) になった曲線がこの印を持っても距離は変わらない。
- **ほぼ直線の曲線は直線にする**: `|P0 − 2C + P1| < 1/1024 em`（弦からのずれ 1/4096 em 以下）。この量が小さい曲線は、閉形式の三次方程式の
  係数が小さくなって float で条件が悪くなる。
- 制御点の差が ±0.49em を超える曲線は de Casteljau で 2 分する（正確）。
- 量子化で長さ 0 になったセグメントは除く。

### 3.3 グリッド

- セルは `1/indexEm` em 角（既定 1/16 em）。グリフのグリッドは quad を覆う（左下のセル `floor(em × indexEm)`・単精度の quad をわずかに広げて覆う）。
- セルに書く**項目番号**はセグメントの始点の項目の番号＋1（0 は空き）。セルの集合は「セルの閉じた面積のどこかから見て最近傍になるセグメント」（§4.3）で、
  曲線が先・直線が後で、それぞれの中はセルの中心に近い順（§4.3 の 4）。空きの 0 は後ろに置く（シェーダは先頭から本数だけを解く）。
- セルは**項目番号 2 つ** `(a, b)`。セグメントが 2 本以下のセルは番号そのもの（1 本は `(a, 0)`・空のセルは `(0, 0)`）。3 本以上のセルは番号を
  **レコード**に置き、`(レコードの位置の下の桁, 印)` と書く。レコードはセグメントテーブルの直前に並び、位置 `o` はセグメントテーブルの先頭からの**後ろ向きの texel の差**
  ＝レコードの番地 `dataBase − o`。**短いレコード**（3 本か 4 本）は番号 4 つ（3 本は 4 つ目が 0）、**長いレコード**（5 本以上）は
  `[セグメントの数, 番号, 番号, …]`（texel の境まで 0 で埋める）。**同じ内容（番号の列が同じ）のレコードは、グリフの中で 1 つにまとめる**。
- **印**は番号の最大の値 `T` から下へ 4 つ（`RinkakuEncoding.RecordMarker`）: `T − b` の下の 1 ビットが長いレコードか（0＝短い・1＝長い）、その上の
  1 ビットが `o` の上の桁 `h`。`o = a + h × 2^n`（`n` は番号のビット数）。
- **ナローインデックス**（項目が 252 以下で、レコードの並びが 511 texel 以下のグリフ）: 番号は 8bit（`T` = 255・印は 252〜255・セグメントの番号は 1〜251）。
  **texel 1 つにセル 2 つ**を詰める——グリッドの x が偶数のセルが前半（R G）、奇数のセルが後半（B A）。ブロックの左端の texel は偶数のセルから
  始まる（`RinkakuEncoding.BlockOriginCell`）ので、グリッドの左端が奇数なら最初の texel の前半は使わない（0）。短いレコードは texel 1 つ。
- **ワイドインデックス**（それ以外のグリフ）: 番号は 16bit（下位が先・`T` = 0xFFFF）。**texel 1 つにセル 1 つ**。短いレコードは texel 2 つ。
- 1 画素の仕事は、セルの読み出し（3 本以上のセルはレコードの読み出しを 1 回足す）と、その本数の厳密距離（評価本数の上限は 32・実測は §7）。

### 3.4 セルと UV

`RinkakuGlyphCell`（グリフインデックスで引く）:

| フィールド | 意味 |
|---|---|
| `page` | ページ番号 |
| `gridX`・`gridY`・`gridWidth`・`gridHeight` | グリッドの左下のセル（`floor(em × indexEm)`）とセルの数 |
| `blockX`・`blockY` | ページの上のインデックスブロックの左下（texel） |
| `dataBase` | セグメントテーブルの最初の項目の線形の番地 |
| `wide` | ワイドインデックスか（texel 1 つにセル 1 つ・番号 16bit） |
| `planeLeft`…`planeTop` | quad（em） |

画素の em 座標 `p` のセルは `c = floor(p × indexEm)`。ナローインデックスの texel は `(c.x >> 1, c.y) + K`（前半か後半かは `c.x & 1`。`>>` は符号を保つ
シフトで、負のセルでも `floor(c.x / 2)`）、`K = (blockX − (gridX >> 1), blockY − gridY)`。ワイドインデックスの texel は `c + K`、`K = (blockX − gridX, blockY − gridY)`。
ブロックの幅（texel）は `RinkakuEncoding.BlockWidth`。
`K` は x・y に `64` を足して x を 13bit・y を 11bit に詰める（`RinkakuEncoding.OffsetBias`・`OffsetXBits`・`OffsetYBits`）——頂点の UV に 24bit で
持てる。インデックスブロックは `K` が収まる行（1960 行）までに置く。

**頂点**（`RinkakuRepresentation.WriteGeometry`）: quad は plane の 1 枚。**UV0.x＝`K` を詰めた値**（`RinkakuEncoding.PackedOffset`）、**UV0.y＝`dataBase`**
（ワイドインデックスは `−dataBase`・`PackedDataBase`。セグメントテーブルはインデックスブロックより後ろの行なので 0 にならない）。quad の 4 頂点で同じ値で、どちらも 2^24 未満の
整数なので float で正確に持てる。シェーダは補間しない（`nointerpolation`）で受ける——補間すると丸めで 1 ずれうる。UV0.zw は T2Font の器が書く em 座標。

### 3.5 グリフ表現とシェーダ

- **グリフ表現** `RinkakuRepresentation`: セル・ページ・`indexEm` を持つ。`indexEm` をマテリアルの `_IndexEm` に載せる（`ConfigureMaterial`）ので、
  マテリアルを共有してよい範囲（`MaterialScope`）はグリフ表現自身＝フォントごと。テクスチャもフォントの境で替わるので、バッチの割れ方は SDF と同じ。
- **シェーダ** `Rinkaku/Glyph`（`#pragma target 3.5`）: texel を `Load` で整数の番地から引く（ページの高さを知らずに線形の番地を 2 次元へ直せ、UV の
  丸めの誤差も無い）。頂点と、面と縁取りの合成（S1〜S9）は T2Font の SDF のシェーダと同じで、距離の求め方だけが違う:
  1. UV0.xy から `K` と `dataBase` を取り、`floor(p × _IndexEm)` のセルの番号 2 つを読む（ナローインデックスは texel の半分）。3 本以上のセルはレコードを 1 回読む（長いレコードは続きの texel も）。
  2. セグメントごとに項目の 3 texel（始点・制御点の差・次の項目の始点＝終点）を読む。**3 点の AABB までの距離（セグメントまでの距離の下限）が今の最短より
     遠いセグメントは解かずに飛ばす**（セルのセグメントは曲線・直線のそれぞれの中で中心に近い順に並ぶので、近いセグメントを先に解いて飛ばしが効く・§4.3）。**制御点の差が (0, 0) の項目（直線）は
     正射影で測る**: t を 0〜1 に丸め、丸めたかで端を決めて同じ枝の中で整数に書く（帯の境で途中と端を取り違えても、そこでは接線の法線と擬似法線の符号が
     一致する）。ウェーブの中で直線と曲線が混ざれば両方の手順を進む。曲線のセグメントは、2 次ベジエへの最短距離を
     閉形式で解いて Newton 法の 1 反復で解をリファインし、**両端の距離も必ず比べて、同じ近さ（1e−6 em の幅の中）なら端を選ぶ**。頂点が最近傍になる楔の中では、端の擬似法線でなければ符号を決められない
     （接線の法線で決めると、鋭い角の楔の中で符号を誤り、角から伸びる楔や細い線が描かれる）。閉形式の根は GPU の精度（acos・pow の近似、掛け算と
     足し算のまとめ方）で端からわずかにずれうるので、端は根に頼らずに比べる。
  3. 最も近いセグメントの向きで符号を決める（内点は接線の右手の法線・端点は擬似法線）。**端を選んだことは手順 2 の端を選んだ枝の中で整数に書き**、後から
     t と 0・1 を比べて決め直さない（D3D11 の GPU で、t がちょうど 1.0 なのに `t >= 1.0` の枝が通らず、終点を接線の法線で判定したことがある）。
     擬似法線（項目の 2 つ目の texel の w）は、最も近いセグメントが端で決まったときにだけ、ループの後で 1 回読んで復号する。
  4. 得た符号付き距離（em）で、SDF のシェーダと同じ式でエッジスタイルを塗る。
- 距離の求め方（1〜3）は `RinkakuDistance.hlsl` に置き、グリフ表現のシェーダはそれを取り込む。GPU の途中の値を読む計測のシェーダも同じ手順を取り込めるように、
  `RinkakuSignedDistance` は最も近いセグメント・t・両端の距離・符号を決めた法線を `RinkakuTrace` に出す（グリフ表現のシェーダは読まないのでコンパイラが消す）。
- セル 1 つのセグメントの数は `RinkakuEncoding.MaxItemsPerCell`（32）までで、シェーダのループの上限と同じ。超えるセルを作る字はベイクの失敗にする。
- 単精度での誤差は、シェーダの手順を写した C# のモデルと倍精度の読み戻しの差で測った（M+ 1c・IPAex 明朝・M+ 2p heavy の字で最大 1e−6 em。ほぼ全部が
  手順 2 の端を選ぶ幅で、192px で 0.0002px）。

## 4. ベイクの算法

### 4.1 和集合輪郭

重なった輪郭・逆向きの輪郭・辺を共有して接する輪郭を、**非ゼロ巻き数で塗った領域の境界**へ作り直し、全部のセグメントを塗る側が右手に向くようにする。
重なりの内側の辺が残ると、字の中にその辺への距離の筋が出る（縁取りが字の中に描かれる）。

1. 座標が一致する端点は輪郭をまたいで 1 つの頂点にする。
2. セグメントどうしの交点を求める: 制御点の AABB で 2 分して絞り、弦で交わる所を求め、元の曲線の上で Newton 法で詰める。平行で同じ直線に乗る辺は、
   互いの端点のうち相手の内側にあるものを交点にする。同じセグメント（向きは問わない）の重なりは分けない。
3. 交点でセグメントを分ける（de Casteljau・端点は共有の頂点に揃える）。
4. 分けた片の中点から左右へ 1e−7 em ずらした点の巻き数を元の全セグメントで数え、**片側だけが塗られる片**を残し、塗る側を右手へ向ける。同じ片の重複を除く。
5. 頂点で片を繋いで輪郭にする。頂点から進む片が複数あれば（輪郭が点で接する）、同じ元の輪郭の片を先に、次に最も右へ曲がる片を選ぶ。

**繋げない字はインポートの失敗**にし、字を名指す（黙って生の輪郭を使わない）。直すのは元フォントの側。

### 4.2 符号化

§3.2 のとおり。直線化・分割・量子化・長さ 0 のセグメントの除去の後で、頂点ごとの擬似法線を求める。座標が −1〜3em の外に出る字はインポートの失敗。

### 4.3 インデックスの構築

量子化した値を元に戻したセグメント（シェーダが評価する幾何と同じ）で、セルごとに:

1. セルの中心からセグメントへの距離を取り、最小＋セルの対角の長さを超えるセグメントを外す。距離は 1-Lipschitz なので、外したセグメントがセルの中で最近傍になる
   ことは無い（証明付きの上位集合）。セグメントの制御点の AABB までの距離はセグメントまでの距離の下限なので、下限が明らかに大きいセグメントは厳密な距離を
   解かずに外す。1 本ならそれを書く。
2. 2 本以上なら、まずセルの中を通るセグメントを入れる（その上の点では距離 0 の最近傍なので必ず要る・セルの角をかすめるだけのセグメントも落とさない）。
   次にセルの閉じた面積を 7×7 のグリッドでサンプリングし（角と辺を含む）、隣り合うサンプルで最近傍が変わる所を 4 段まで 2 分して詰め、
   見つけた最近傍の和を書く。2 分は、その区間で 3 本目が最近傍になりうると Lipschitz で言えるときだけ下る。残る取りこぼしはサンプルの線から外れた、
   サンプルの間隔より細い領域だけで、その中の距離の誤差は Lipschitz からその幅の 2 倍以下に限られる。
3. 上位集合をそのまま書かないのは、角の外側（頂点が最近傍になる楔の領域）では隣り合う 2 セグメントへの距離が同じ頂点への距離で等しく、上位集合が
   いつも 2 本以上になるため。どちらを評価しても距離も符号（頂点の擬似法線は両方のセグメントが同じ項目から読む）も同じなので、サンプリングで
   1 本（番号の小さい方）に決める。
4. セルのセグメントは**曲線を先・直線を後**に、それぞれの中は**セルの中心に近い順**（同じ距離は番号の順）に書く（出力のバージョン 4）。GPU は
   8×8 画素などのウェーブを同じ命令列で進め、ループのある周でどれか 1 画素でも曲線を解けばウェーブ全体が曲線の手順を進むので、曲線を前の周へ
   集めると曲線の手順を進めるループの回数が減る（本文の大きさで時間 −4〜−7%・§7）。直線かどうかは直線の印（§3.2）で分ける。シェーダは AABB が今の最短より遠いセグメントを解かずに飛ばすので（§3.5）、
   最も近くなりやすいセグメントを先に解くほど飛ばしが効く。

セグメントへの距離は、直線なら正射影、曲線なら距離の二乗の導関数（三次式）の極小を、その極値（2 次方程式の根）で分けた単調な区間ごとに挟み込み付きの
Newton 法で求める。量子化した制御点が弦の上（始点と終点の間）にちょうど乗るセグメントは直線そのものなので直線として測る（量子化した値は 2 進の
有限小数で、この判定は倍精度で厳密）。

### 4.4 配置

§3.1 のとおり。セグメントテーブルは「レコードの並び → 項目の列」の順に並べ、`dataBase` は項目の列の先頭。

## 5. ベイク仕様（`"kind": "rinkaku"`）

| 設定 | 既定 | 意味 |
|---|---|---|

- **ベイク仕様に無い設定**（C# から `RinkakuAtlasBaker.Bake` を呼ぶときだけ選べる）: `RinkakuBakeSettings.CellOrder` はセルのセグメントの並び。既定の
  `CurvesFirst` は曲線を先・直線を後（§4.3 の 4）。`NearFirst` は曲線と直線を分けずにセルの中心に近い順に並べる——並びを比べる計測のための

  `Rinkaku/Glyph` と 3 桁まで同じ）。解く＝全部 − 読むが解かない（三次方程式と直線の正射影）、セグメントの読み＝読んで全部 − 読まずに全部、固定オーバーヘッド＝セルだけ、残り＝
  ループの制御・セルの復号・AABB の検査・擬似法線の後読み。括弧は「全部」に対する割合。出力のバージョン 3。読まずに解く変種は直線か曲線かを読めない
  ので、番号から擬似乱数で約 3/4 を直線として解く（セグメントの読みの取り分は近似）。

  下がり、セグメントの読み 20〜37%・固定オーバーヘッド 8〜28% が相対的に大きくなった。セグメントの読みは、先読みで依存の深さを半分以下にしても変わらなかった分なので（バージョン 2）、

  ±数 % の幅で見る。
- 残る手立ては、項目を 1 texel に詰める形式・効果の外延の宣言（quad の画素を減らす）。

| 128 | 0.0012／0.0092 | 8／1544 | 0.0006／0.0035 | 7／324 |
| 192 | 0.0008／0.0090 | 3／3497 | 0.0004／0.0035 | 13／1229 |

- SDF の誤差の大きい画素は大きさとともに増える（角の丸まり＝em48 の texel が表示で数画素になる）。Rinkaku は大きさに依らず数画素で、距離のランプと
  面積が角で食い違う分（距離を SDF と同じ意味で持つ限り残る）。
- 40px の外縁だけは Rinkaku の誤差 0.25 超が多い。縁取りの外角は真の距離の円弧（半径 0.08em）で、細い円弧ではランプが面積から離れる。

## 8. 既知の制限

- **点で接する輪郭の頂点**: 2 つの領域が 1 点で接する頂点では、擬似法線が片方の領域の角だけで決まる。その頂点が最近傍になる点のごく一部で符号を
  誤りうる（字の外の 1 点のまわり）。
- **細い取りこぼし**: §4.3 の 2 のとおり、セルを通らないセグメントが、サンプルの線から外れたサンプルの間隔より細い領域でだけ最近傍になると落としうる
  （距離の誤差はサンプルの間隔の 2 倍以下＝`indexEm` 16 で 1/48 em 以下）。§7 の検証では見つかっていない。
- **擬似法線の量子化**: 1.4° の段なので、内角が約 1.4° より鋭い角の先端では、端点が最近傍の点の符号を誤りうる。
- **ほぼ直線の曲線**: 弦からのずれが 1/4096 em 以下の曲線は直線として描く。
