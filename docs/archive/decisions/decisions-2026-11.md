## 2026-11-09 版 0.3.0 を公開し、グリフ表現 Rinkaku を同梱する — D-T2FREPUB

**発端**: v0.2.0 の後、パッケージ T2Font は利用側の開発環境へ写されて開発が続いた（グリフ表現を足すための口・用語の整理）。その上で
新しいグリフ表現 Rinkaku（TrueType の輪郭を 2 次ベジエのまま持ち、最近傍の区間への厳密な符号付き距離で描く）が作られた。これらを公開する。

**決定 1（版）**: タグ `v0.3.0` で、T2Font 0.3.0 と Rinkaku 0.1.0（`Packages/info.someiyoshino.rinkaku/`・MIT）を同じリポジトリから公開する。
導入は git URL かフォルダを写すかの 2 通り（D-T2FONTGIT）。Rinkaku を git URL で入れるときは T2Font を先に同じタグで入れる（各パッケージの README）。

**決定 2（正本と運用）**: パッケージの正本は利用側の開発環境に置き、**版ごとに本リポジトリへ写して公開する**。D-T2FONT の「本リポジトリが
パッケージの正本」を改める。本リポジトリではパッケージの中を直さず（直すと次に写すときに失われる）、Issue とプルリクエストを受け付けない。
検証のプロジェクト（`Assets/`・`Tests/`）は、写した版でコンパイルとテストが通るように合わせるだけにする。Rinkaku のテストと計測の道具は写さない
（検査は利用側で回している。元フォントを本リポジトリへ足さないため）。

**決定 3（DOI）**: リポジトリを Zenodo と連携し、GitHub のリリースごとにソフトウェアの記録と DOI を作る。記録の情報は根の `.zenodo.json` に置く。

**採らなかった案**: 本リポジトリへ開発を戻す（利用側との往復の費用が版ごとの写しより大きい）。Rinkaku を別のリポジトリにする（T2Font の版と
組で使うので、同じタグで配る方が導入を誤りにくい）。
