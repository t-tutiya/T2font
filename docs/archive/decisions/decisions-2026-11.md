## 2026-11-16 「表現」をグリフ表現と書き、用語の表に訳語を足す — D-TERMS2

**発端**: 用語の表（D-TERMS）は「表現」を一般に通じる語として言い換えずにいたが、単独の「表現」は「表現する」の一般の意味と見分けにくく、
何の表現かが文から読み取れない。ほかにも「生成器・鍵・道具・窓」など、一般的でない訳語や、日本語では通じにくい比喩が残っていた。

**決定**: glyph representation は「グリフ表現」と書き、単独の「表現」を使わない（型名 `GlyphRepresentation`・`GlyphRepresentationKind` と
対応する）。generator→ジェネレーター・key→キー・tool→ツール・window→範囲／期間・band（値の範囲）→範囲を表に足し、既存の記述を
書き換えた。本リポジトリではまだ使っていない語（loop→ループ・model→モデル・high-water mark→ハイウォーターマーク・vocabulary→t2s 語彙／
scs 語彙）も、使い始める前に表へ足した。

**採らなかった案**: 「フォント表現」（型名と対応せず、1 フォントに複数のグリフ表現を持たせる拡張 `T2FontAsset.RepresentationOf(glyph)` を
「1 フォントに複数のフォント表現」と書くことになる）。band の訳に「帯域」（周波数の語として読まれる）。

**パッケージとの関係**: パッケージの中の言い換えは正本の開発環境で済み、版 0.3.0 の写しで本リポジトリに入った（パッケージの CHANGELOG の 0.3.0）。本リポジトリでパッケージの中は直さない（D-T2FREPUB）ので、ここで当てるのはパッケージの外（用語の表・`Assets/`・`Tests/`・`Tools/docs-figures/`・文書）だけである。

**守ること**: 一般の意味の「表現する」・回数と実行の「回」・幅を持つ部分の「帯」・比喩の「道具」は言い換えない（用語の表「言い換えないもの」）。
図を作るスクリプト（`Tools/docs-figures/`）の文字列も同じ表に従う。D-TERMS と同じく、歴史記録・公開済みの CHANGELOG・テンプレートが
管理するファイルは書き換えない。

## 2026-11-09 版 0.3.0 を公開し、グリフ表現 Rinkaku を同梱する — D-T2FREPUB

**発端**: v0.2.0 の後、パッケージ T2Font は利用側の開発環境へ写されて開発が続いた（グリフ表現を足すための口・用語の整理）。その上で
新しいグリフ表現 Rinkaku（TrueType の輪郭を 2 次ベジエのまま持ち、最近傍の区間への厳密な符号付き距離で描く）が作られた。これらを公開する。

**決定 1（版）**: タグ `v0.3.0` で、T2Font 0.3.0 と Rinkaku 0.1.0（`Packages/info.someiyoshino.rinkaku/`・MIT）を同じリポジトリから公開する。
導入は git URL かフォルダを写すかの 2 通り（D-T2FONTGIT）。Rinkaku を git URL で入れるときは T2Font を先に同じタグで入れる（各パッケージの README）。

**決定 2（正本と運用）**: パッケージの正本は利用側の開発環境に置き、**版ごとに本リポジトリへ写して公開する**。D-T2FONT の「本リポジトリが
パッケージの正本」を改める。本リポジトリではパッケージの中を直さず（直すと次に写すときに失われる）、Issue とプルリクエストを受け付けない。
検証のプロジェクト（`Assets/`・`Tests/`）は、写した版でコンパイルとテストが通るように合わせるだけにする。Rinkaku のテストと計測の道具は写さない
（検査は利用側で回している。元フォントを本リポジトリへ足さないため）。

**決定 3（DOI）**: リポジトリを Zenodo と連携し、GitHub のリリースごとにソフトウェアの記録と DOI を作る。記録の情報は根の `.zenodo.json` に置く。

**採らなかった案**: 本リポジトリへ開発を戻す（利用側との往復の費用が版ごとの写しより大きい）。Rinkaku を別のリポジトリにする（T2Font の版と
組で使うので、同じタグで配る方が導入を誤りにくい）。
