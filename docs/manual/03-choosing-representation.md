# グリフ表現の選び方（SDF と Rinkaku）

フォントアセットのグリフ表現は、ベイク仕様の `representation` の `kind` で選ぶ。同梱は T2Font の **SDF**（`"kind": "sdf"`）で、Rinkaku の
パッケージを入れると **Rinkaku**（`"kind": "rinkaku"`）も選べる。どちらでベイクしても送り幅とインク境界（タイポグラフィテーブル）は同じなので、
グリフ表現を替えても字の並びは動かず、ホストのコードも変わらない（README §2.3）。

各値の正典は T2Font の README §9（SDF）と Rinkaku の README §2・§5・§7。本書は選ぶための見取り図だけを持つ。

## 1. 比べる

| 観点 | SDF | Rinkaku |
|---|---|---|
| 縁の形 | 角が丸くなる。字を大きく表示するほど目立つ（アトラスの 1 texel が表示で数画素になる） | 輪郭を 2 次ベジエのまま持ち、厳密な距離で描くので、表示の大きさに依らず角が鋭い |
| 描画の費用 | 画素ごとにテクスチャを 1 回読むだけ | 画素ごとに、最近傍のセグメント（たいてい 1〜4 本）への距離を解く。画素あたりの時間は SDF より数倍から 1 桁以上大きい（Rinkaku の README §2・§7） |
| データ量 | 全字が同じ大きさのセル。`R8`（非圧縮）か `BC4`（半分・デスクトップだけ） | 字の形で決まる（画の多い字ほど大きい）。漢字の平均は SDF（em48）の `BC4` よりも小さい。画の密な字は `BC4` を上回ることがある（Rinkaku の README §7） |
| エッジスタイル | 全部の効果 | 全部の効果。値は SDF と同じ意味 |
| 表示サイズ | 14px 以上 | 14px 以上 |
| マテリアル | エッジスタイルが同じなら全 SDF フォントで共有 | フォントごと（README §4.5） |
| シェーダの要件 | `#pragma target 3.0` | `#pragma target 3.5`（整数の番地でテクスチャを読む `Load` を使う） |

バッチは、どちらもフォント（ページ）の境で割れる（README §4.4）。エッジスタイルの値の範囲（縁取りの幅など）は README §6.1 で、どちらでも同じ。

## 2. 選ぶ

- **本文**（字が多く、小さく表示する）: **SDF**。画素あたりの費用が小さく、字の数に強い。
- **大きな字**（タイトル・見出し・拡大の演出・カメラが寄る字）: **Rinkaku**。SDF の角の丸みが見える大きさで効く。字の数が少ないので、費用の差は
  画面全体では小さい。
- 迷ったら、同じ文字列を同じ表示サイズで並べて比べる（[クイックスタート](01-quickstart.md) の 8 の段）。費用は、想定する画面（字の数と大きさ）を
  対象の GPU で測って決める。

**1 つのフォントアセットのグリフ表現は 1 つ**。同じ元フォントから `sdf` と `rinkaku` の 2 つのベイク仕様を作り、用途ごとにフォントアセットを
使い分ける。送り幅は同じなので、同じ文字列の表示を一方から他方へ差し替えても、並びは動かない。

## 3. 設定を調える

ベイク仕様の `representation` の設定（キーと範囲の正典は README §9・Rinkaku の README §5）。

| グリフ表現 | 設定 | 上げると | 下げると |
|---|---|---|---|
| SDF | `emPx`（アトラスの 1em の px） | 角の丸みが小さくなる。データが増える | データが減る。角が丸くなる |
| SDF | `format` | `R8` は全ターゲット | `BC4` はデータが半分になるが、デスクトップだけ |
| SDF | `maxPageSize` | ページの数が減る | 1 ページの大きさの上限が下がり、字の多いフォントはページが分かれる |
| Rinkaku | `indexEm`（1em のグリッドのセルの数） | 1 画素で解く本数が減り、描画が速くなる。データが増える | データが減る。描画が遅くなる |
| Rinkaku | `maxPageSize`（ページの高さの上限） | ページの数が減る | 字の多いフォントはページが分かれる |

## 4. Rinkaku を使うときの注意

- **対応する環境**: シェーダモデル 3.5 以上（OpenGL ES 3.0 相当以上）が要る。パッケージの描画の検証の記録は D3D11 の GPU（Rinkaku の README §2）。
  ほかのグラフィックス API・GPU で使うなら、利用側のテストで適合検査（`GlyphConformance.CheckRendering`・README §10）を回して確かめる。
- **切り替え**: Rinkaku を描けない環境向けの自動の切り替えは無い。SDF でベイクしたフォントアセットも用意し、ホストがどちらを使うかを決める
  （どちらもタイポグラフィテーブルは同じ）。
- **既知の制限**: 点で接する輪郭の頂点・ごく鋭い角の先端など、ごく一部の点で符号を誤りうる（Rinkaku の README §8）。
