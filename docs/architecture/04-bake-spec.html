1ベイク仕様とは

ベイク仕様（.t2font）は、どの元フォントから・どの字を・どの表現でベイクするかを書いた JSON のテキストファイル。Unity がこのファイルを見つけると、パッケージのインポーター T2FontImporter（拡張子 t2font の ScriptedImporter）がインポートし、T2FontAsset（メインアセット）と、表現とページのテクスチャ（サブアセット）を作る。

アセットは生成物で、Unity の Library に作られる。リポジトリに置くのはベイク仕様と元フォントだけ（README §2.4）。実行時に元フォントは要らない——T2FontAsset はタイポグラフィテーブルと表現を自分で持ち、元フォントを参照しない。

2フォントアセットを作る

新しいフォントを T2Font で使えるようにするまでの手順。どれも Unity のエディタの中で済み、コードは書かない。

2.1元フォントを置く

  1. 元フォントのファイルを、プロジェクトの Assets/ の下に置く（本プロジェクトは Assets/Authoring/Fonts/）。パッケージの中のフォントは Packages/<パッケージ名>/… のままでよい。
  2. フォントは TrueType 輪郭（glyf）の単体のフォントであること。拡張子が .ttf のものはたいていこれに当たる。フォントコレクション（.ttc）と、CFF 輪郭のフォント（.otf の多く）は読めない。読めないときはインポートが失敗し、文面がそう名指す（§8.6）。
  3. フォントのライセンスが、ゲームへの組み込みと、ベイクした派生物（アトラスのテクスチャ）の配布を許すことを確かめる。

Unity は .ttf を自分の Font アセットとしてもインポートするが、T2Font はそれを使わない。インポーターはファイルのバイト列を直接読む。

2.2ベイク仕様を書く

  1. 拡張子が .t2font のテキストファイルを Assets/ の下に作る（本プロジェクトは Assets/Content/Fonts/）。Unity の Create メニューには項目が無いので、エクスプローラーやテキストエディタで作る。見本の mplus-1c-sdf.t2font を複製して書き換えるのが早い。Windows のエクスプローラーで拡張子を隠していると …t2font.txt になりやすいので、拡張子を表示にしておく。
  2. 文字コードは UTF-8 で保存する。
  3. ファイル名（拡張子を除く）がアセットの名前になる。サブアセットの名前の頭にも付く（名前 (sdf)・名前 page 0）。
  4. 下の形から書き始め、元フォントのパスと字を直す。省いた SDF の設定は既定値になる（§4.5）。
{
    "source": "Assets/Authoring/Fonts/使うフォント.ttf",
    "coverage": "fixed",
    "charsets": ["Ascii"],
    "representation": { "kind": "sdf" }
}

見本のベイク仕様は次のとおり。先頭の // の行はコメント。

// 検証用の M+ 1c を SDF でベイクするベイク仕様（パッケージの README §7）。インポートの EditMode テスト・適合検査・比較の場面が読む。
// 適合検査の描画は「■」を基準の字にする（インク部が中央の列を上下の水平な縁で横切る塗りつぶしの字）。
{
    "source": "Assets/Authoring/Fonts/mplus-1c-regular.ttf",
    "coverage": "fixed",
    "charsets": ["Ascii"],
    "characters": "いろはにほへとちりぬるをわかよたれそつねならむうゐのおくやまけふこえてあさきゆめみしゑひもせすんアイウエオカキクケコサシスセソタチツテトナニヌネノ永東京都一二三色香散我誰常有為奥山今日越浅夢見酔字形表現縁取■□、。「」・ー",
    "representation": { "kind": "sdf", "emPx": 48, "format": "R8" }
}

2.3インポートを確かめる

  1. ファイルを保存して Unity のエディタに戻ると、変更が見つかってインポートが始まる（Preferences の Asset Pipeline > Auto Refresh が有効のとき。無効なら Assets > Refresh）。
  2. 成功すると Console に報告が 1 行出る。見本では次のとおり（最後はベイクにかかった秒）。
    [T2Font] Assets/Content/Fonts/mplus-1c-sdf.t2font: 206 字・グリフ 207・sdf・1 ページ（1020×1008・R8）・セル 68×72（インク境界 (-0.01, -0.23, 0.982, 0.842)）・n.n 秒
    「字」はタイポグラフィテーブルに入った字の数、「グリフ」はそれに .notdef などの cmap を持たないグリフを足した数。固定の文字セットに元フォントの無い字があれば、末尾に「固定の文字セットのうち元フォントに無い字 N 字」が付く（§5）。
  3. 失敗すると Console に赤い誤りが出て、アセットは作られない。文面の頭にベイク仕様のパス、ベイク仕様の誤りなら行番号が付く。直し方は §8。
  4. Project ウィンドウでベイク仕様を開く（▶）と、メインアセットの T2FontAsset の下に、表現（名前 (sdf)）とページのテクスチャ（名前 page 0 …）が並ぶ。Inspector で中身を見られるが、生成物なので書き換えられない。

和文の本文フォント（数千字）は、インポートに数十秒かかる。インポートは Unity の Library に残るので、ベイク仕様と元フォントを変えない限り、エディタを開き直してもやり直さない。

2.4使う

  • 検証ビューで見る: Canvas の下の GameObject に T2FontText（パッケージの Viewer）を足し、Font の欄へ T2FontAsset（ベイク仕様の ▶ の中のメインアセット。ベイク仕様そのものをドラッグしてもよい）を入れる。文字列・表示サイズ・エッジスタイルを Inspector で替えられる。
  • コードから使う: [SerializeField] T2FontAsset の欄に入れて参照する。シーンやプレハブから参照されたアセットはビルドに入る。エディタのコードからは AssetDatabase.LoadAssetAtPath<T2FontAsset>("…/名前.t2font") で読め、インポートが失敗していれば null が返る。
  • 字を置く API（Resolve・Metrics・RepresentationOf）は README §3.1、描き方は 03 章。

2.5直す

ベイク仕様を書き換えて保存すれば、再インポートされる。元フォントを差し替えたときも再インポートされる（いつ再インポートされるかは §9）。サブアセットはインポーターが決まった識別子で足すので、再インポートしてもシーンやプレハブからの参照は外れない。

3書式の決まり

  • JSON。最上位は { … } のオブジェクト 1 つで、その後ろにはコメントしか置けない。
  • // から行末まではコメント。ファイルの読み方の説明をここに書く。
  • 未知のキー・重複したキー・型の違う値は、インポートの失敗（README §2.1）。綴りの誤りを既定値で読み替えて、意図と違うフォントが黙ってできることはない。
  • キーの名前・文字セットの名前・kind・format などの値は、大文字と小文字を区別する。
  • キーの順番は自由。
  • 数は数で書く（48 や 0.5）。"48" のように引用符で囲むと文字列になり、失敗する。
  • 文字列の中の " と \ は \"・\\ と書く。どの字も \uXXXX で書ける（BMP の外の字はサロゲートペアの 2 つ、例: \uD842\uDFB7＝𠮷）。字をそのまま書いてもよい。

4キー

最上位のキーは次の 5 つだけ。

キー必須型値
source必須文字列元フォントのプロジェクトパス
coverage必須文字列"corpus" か "fixed"
charsetsどちらか文字列の配列固定の文字セットの名前
charactersどちらか文字列足す字（指定文字）
representation必須オブジェクト{ "kind": "種類", … }

「どちらか」は、charsets と characters の少なくとも一方で字を 1 つ以上指定すること。両方を書けば和になる（§5）。

4.1source

元フォントのプロジェクトパス。プロジェクトのルートからの相対で、Assets/ か Packages/ で始め、区切りは /（\ は失敗）。ファイル名だけや、C:/… のようなディスクの上のパスは書けない。

"source": "Assets/Authoring/Fonts/mplus-1c-regular.ttf"
  • ファイルが無ければインポートの失敗。
  • インポーターは元フォントに依存を張るので、元フォントを差し替えると再インポートされる。
  • 同じ元フォントを、字や設定を変えて何通りにもベイクできる——ベイク仕様を別のファイルにして、同じ source を指す。

4.2coverage

このフォントが本文をどこまで覆うべきか。

値意味
"corpus"本文フォント。本文（シナリオなど）に出る全字を覆うべきフォント
"fixed"固定の文字セットだけを持つ装飾書体（タイトル・数字など）。欠けた字は実行時の代替グリフで見せる

インポーターはこの値で振る舞いを変えない。値はアセットにも入らない。検査の厳しさを決めるのは利用側で、たとえば「本文の全字が corpus のフォントにあるか」を確かめる利用側の検査が、ベイク仕様を読んで（FontBakeSpec.Parse の Coverage）フォントを分ける。

4.3charsets

固定の文字セットの名前の配列。名前の一覧と中身は §6。

"charsets": ["Ascii", "JisX0208"]
  • 複数を書くと和になる。同じ名前を 2 度書いても、重なった字を書いても 1 字になる。
  • 名前は列挙子の綴りそのもの（大文字小文字も区別する）。知らない名前は失敗で、文面に使える名前が並ぶ。
  • 文字列 1 つ（"Ascii"）は配列ではないので失敗。1 つでも ["Ascii"] と書く。
  • 固定の文字セットは上限集合で、元フォントに無い字は失敗にせず、件数だけを報告して飛ばす（§5）。

4.4characters

足す字（指定文字）を 1 本の文字列で書く。字の順番と重なりは問わない。

"characters": "■□、。「」・ー𠮷"
  • 字はコードポイントの単位で数える。サロゲートペアは 1 字。結合文字や異体字セレクタも、それぞれ 1 つのコードポイントとして足される（T2Font は字を組み合わせない）。
  • 制御文字（U+0000〜U+001F・U+007F）と BOM（U+FEFF）は足さずに読み飛ばす。片割れのサロゲート（\uD842 だけ）は失敗。
  • 元フォントに無い字は、インポートの失敗（README §2.1）。作者が名指した字を黙って捨てない。文面に無い字が最大 40 字並ぶ。
  • 空白も字。characters だけで作るフォントで空白を描くなら、" "（U+0020）や全角の空白（U+3000）を書き入れる。収録していない字は実行時に代替グリフになり、誤りが記録される（README §3.1）。

本文の字だけを収める出荷のフォントは、本文から字を集めて characters に書いたベイク仕様にする。そのような道具は利用側が作り、パッケージは書き出しの API を持つ: FontBakeSpec.WithCharacters（字を指定文字だけに替え、固定の文字セットを外す）と ToJson（全キーを省略せずに書く）。書き出した例は §7.2。

4.5representation

グリフの表現の種類と、その種類の設定。kind は必須で、既定の表現は無い。kind 以外のキーは、その種類の記述子が検査する（README §7.4）。パッケージが持つ種類は "sdf" だけで、ほかの種類は別のパッケージが足す。知らない種類は失敗で、文面に使える種類が並ぶ。

"kind": "sdf" の設定

キー型範囲既定意味
emPx数8〜25648アトラスの上の 1em の px。小数も書ける
format文字列"R8"・"BC4""R8"ページのテクスチャの形式。R8 は非圧縮でどのターゲットでも使える。BC4 は R8 の半分の大きさで、ビルドのターゲットがデスクトップ（Windows・macOS・Linux）のときだけ使える（ほかのターゲットではインポートの失敗）
maxPageSize整数64〜1638481921 ページの幅と高さの上限（px）。字がページに収まらないときだけ、ページを分ける

emPx を上げると、大きく表示したときの角や細い線が正確になる代わりに、テクスチャが emPx の 2 乗で大きくなる。表示サイズは emPx と別で、1 枚のアトラスから小さい字も大きい字も 1 表示 px の AA で描ける（同梱の SDF は 14px 以上・README §4.3・02 章 §8）。下の表は、見本の元フォントに DevelopmentDefault（§6.7）を当てた 6,433 個のインクのあるグリフでの見積もり。

5字が決まるまで

インポーターがベイクする字は、charsets の文字セットの和 ∪ characters の字のうち、元フォントの cmap にある字。それに元フォントの glyph 0 を .notdef（代替グリフ）として必ず足す。収録していない字は、実行時に .notdef で描かれる（README §3.1）。

元フォントに無い字の扱いが、2 つのキーで違う。

charsets（固定の文字セット）characters（指定文字）
何を足すか名前の付いた字の集まり書いた字そのもの
元フォントに無い字飛ばして続ける。報告の末尾に件数だけを出す（警告にしない）インポートの失敗。無い字を文面で名指す
考え方上限集合——「あれば入れる」要求——「必ず要る」
使いどころ開発中に広く収める必ず要る字・出荷する字

たとえば見本の元フォント（M+ 1c）に DevelopmentDefault を当てると、6,442 字（グリフ 6,443）が入り、元フォントに無い 3,288 字は件数だけが報告される。同じ字を characters に書けば失敗する。

タイポグラフィテーブルの字はコードポイントの昇順に並び、字はそこから二分探索でグリフインデックスになる（README §3.2・02 章 §5）。

6.1Ascii

ASCII の印字可能文字。空白（U+0020）から ~（U+007E）まで。制御文字と DEL（U+007F）は含まない。半角の英数字と記号で、全角の英数字（U+FF01〜）は JisX0208 と CommonSymbols にある。英数字だけの UI のフォントはこれ 1 つでよい。文字リストは 付録 A.1。

6.2JisX0208

JIS X 0208 の全字。日本語の文章のほとんどはこの範囲で書ける。

部分区字数中身
非漢字1〜8 区524記号・全角の英数字・ひらがな・カタカナ・ギリシャ文字・キリル文字・罫線
第 1 水準漢字16〜47 区2,965よく使う漢字。読みの順
第 2 水準漢字48〜84 区3,390それに次ぐ漢字。部首の順
  • Unicode へは JIS の標準の対応表で写す。たとえば 1 区 33 点の「〜」は U+301C（WAVE DASH）で、Windows の IME で打つと入る U+FF5E（～）ではない。Windows の側の字は WindowsVariants が持つ。
  • 半角カタカナ（U+FF61〜U+FF9F）は JIS X 0208 に無く、CommonSymbols の「半角／全角形」にある。
  • JIS X 0208 に無い漢字（JIS X 0213 の第 3・第 4 水準の字、人名の異体字など）は入らない。IbmExtensions がその一部を持つ。ほかに要る字は characters に書く。

文字リストは 付録 A.2（区ごと）。

6.3WindowsVariants

Windows（CP932）が、JIS X 0208 の同じ字を、JIS の標準と別の Unicode の字へ写すもの。Windows で書いた文章（IME で打った字・Shift_JIS のファイルから直した字）にはこちらが入るので、JisX0208 の側と両方を収める。字の対応は 付録 A.3。

6.4NecRow13

NEC 特殊文字（CP932 の 13 区）。丸数字 ①〜⑳・ローマ数字 Ⅰ〜Ⅹ・単位の組み文字（㍉ ㌔ ㎝ など）・㈱ № ℡・〝〟・数学の記号の一部。Windows の IME で打て、文章に混じりやすい。CommonSymbols と大きく重なる（上の重なりの表）。文字リストは 付録 A.4。

6.5IbmExtensions

IBM 拡張（CP932 の 0xFA40〜0xFC4B）。小文字のローマ数字 ⅰ〜ⅹ・記号（￤ ＇ ＂ など）と、JIS X 0208 に無い漢字——人名に多い異体字（髙・﨑・德 など）を含む。Windows の IME で打てるので、開発中に字の欠けを意識しないために収める。ローマ数字 Ⅰ〜Ⅹ・㈱・№・℡ などは NecRow13 と重なる。文字リストは 付録 A.5。

8インポートの失敗と直し方

下の例は、次の基本の形を 1〜2 行だけ書き換え、インポーターと同じ手順（ベイク仕様の読み取り → タイポグラフィテーブル → SDF のベイク）に通して出た文面。文面の頭のパスは例のファイル名 Assets/Content/Fonts/example.t2font、行番号は基本の形を書き換えた後のもの。

{
    "source": "Assets/Authoring/Fonts/mplus-1c-regular.ttf",
    "coverage": "fixed",
    "charsets": ["Ascii"],
    "representation": { "kind": "sdf", "emPx": 48, "format": "R8" }
}

8.1JSON の構文

JSON として読めないときの文面の後半は、JSON のリーダー（Newtonsoft.Json）の英語の文面になる。line と position が場所。

カンマが無い（行末の , を落とした）

"coverage": "fixed"
Assets/Content/Fonts/example.t2font: JSON として読めません: After parsing a value an unexpected character was encountered: ". Path 'coverage', line 4, position 4.

直し方: 示された行の前の行の末尾に , を足す。最後のキーの後ろには付けない。

オブジェクトの後ろに余計な内容（} が 1 つ多い）

}
}
Assets/Content/Fonts/example.t2font: JSON として読めません: Additional text encountered after finished reading JSON content: }. Path '', line 7, position 0.

直し方: 括弧の対応を直す。最上位のオブジェクトの後ろには、コメントしか置けない。

重複したキー

"coverage": "fixed",
"coverage": "corpus",
Assets/Content/Fonts/example.t2font: JSON として読めません: Property with the name 'coverage' already exists in the current JSON object. Path 'coverage', line 4, position 15.

直し方: どちらかを消す。後に書いた方が勝つ、という読み方はしない。

8.2共通のキー

キーの綴りの誤り（charsets を charset と書いた）

"charset": ["Ascii"],
Assets/Content/Fonts/example.t2font: 4 行目: 未知のキー "charset" です（キーは source・coverage・charsets・characters・representation）。

直し方: 文面に並ぶキーの綴りに直す。

必須のキーが無い

（source の行を消す）
Assets/Content/Fonts/example.t2font: キー "source" がありません。

直し方: キーを書く。coverage と representation も必須。

source がプロジェクトパスでない

"source": "mplus-1c-regular.ttf",
Assets/Content/Fonts/example.t2font: 2 行目: source はプロジェクトパス（Assets/ か Packages/ で始まり、区切りは /）で書いてください: "mplus-1c-regular.ttf"

直し方: Assets/ か Packages/ から書く。Project ウィンドウでフォントを右クリック → Copy Path で得られる。

coverage の値の誤り（大文字で始めた）

"coverage": "Fixed",
Assets/Content/Fonts/example.t2font: 3 行目: coverage は "corpus" か "fixed" です: "Fixed"

直し方: 小文字の "corpus" か "fixed" にする。

8.3字

知らない文字セットの名前

"charsets": ["JIS"],
Assets/Content/Fonts/example.t2font: 4 行目: 未知の文字セット "JIS" です（名前は Ascii・JisX0208・WindowsVariants・NecRow13・IbmExtensions・CommonSymbols・DevelopmentDefault）。

直し方: 文面に並ぶ名前に直す（§6）。

charsets が配列でない

"charsets": "Ascii",
Assets/Content/Fonts/example.t2font: 4 行目: charsets は文字セットの名前の配列にしてください。

直し方: 1 つでも ["Ascii"] と角括弧で囲む。

字が 1 つも無い

"charsets": [],
Assets/Content/Fonts/example.t2font: charsets か characters のどちらかで字を指定してください（字の無いフォントは作れません）。

直し方: 文字セットの名前を入れるか、characters を書く。

指定文字が元フォントに無い

"characters": "😀",
Assets/Content/Fonts/example.t2font: characters の字が元フォント Assets/Authoring/Fonts/mplus-1c-regular.ttf にありません（1 字）: 😀(U+1F600)

直し方: その字を持つフォントにするか、characters から外す。「あれば入れる」でよい字なら、characters ではなく文字セットの側で収める（§5）。

8.4表現の設定

表現の節の誤りは、文面に representation: が付く。

representation が無い

（representation の行を消す）
Assets/Content/Fonts/example.t2font: キー "representation" がありません（表現の種類を { "kind": … } で選んでください。種類は sdf）。

直し方: "representation": { "kind": "sdf" } を書く。既定の表現は無い。

知らない表現の種類

"representation": { "kind": "msdf" }
Assets/Content/Fonts/example.t2font: 5 行目: representation: 未知の表現の種類 "msdf" です（種類は sdf）。

直し方: 文面に並ぶ種類にする。ほかの種類は、それを足すパッケージを入れると使えるようになる。

SDF の設定のキーの綴りの誤り

"representation": { "kind": "sdf", "emSize": 48 }
Assets/Content/Fonts/example.t2font: 5 行目: representation: 未知のキー "emSize" です（キーは emPx・format・maxPageSize・cellBox）。

直し方: 文面に並ぶキーの綴りに直す。

emPx が範囲の外

"representation": { "kind": "sdf", "emPx": 512 }
Assets/Content/Fonts/example.t2font: 5 行目: representation: emPx は 8〜256 にしてください: 512

直し方: 8〜256 にする。

数を文字列で書いた

"representation": { "kind": "sdf", "emPx": "48" }
Assets/Content/Fonts/example.t2font: 5 行目: representation: emPx は数にしてください。

直し方: 引用符を外す。

format の値の誤り

"representation": { "kind": "sdf", "format": "R16" }
Assets/Content/Fonts/example.t2font: 5 行目: representation: format は "R8" か "BC4" です: "R16"

直し方: "R8" か "BC4" にする。BC4 はデスクトップのターゲットだけ（Android などへ切り替えると、インポートが失敗して R8 にするよう文面が言う）。

maxPageSize が整数でない

"representation": { "kind": "sdf", "maxPageSize": 1000.5 }
Assets/Content/Fonts/example.t2font: 5 行目: representation: maxPageSize は 64〜16384 の整数にしてください: 1000.5

直し方: 64〜16384 の整数にする。

cellBox の数が 4 つでない

"representation": { "kind": "sdf", "cellBox": [0, -0.2, 1] }
Assets/Content/Fonts/example.t2font: 5 行目: representation: cellBox は [左, 下, 右, 上]（em）の 4 つの数にしてください。

直し方: [左, 下, 右, 上] の 4 つの数にする。

cellBox の幅か高さが 0 以下

"representation": { "kind": "sdf", "cellBox": [0, 0, 0, 1] }
Assets/Content/Fonts/example.t2font: 5 行目: representation: 箱の大きさが 0 以下です（0, 0, 0, 1）。

直し方: 右 > 左・上 > 下 にする。

8.5ベイク

cellBox からはみ出す字がある

"representation": { "kind": "sdf", "cellBox": [0, -0.25, 1, 0.8] }
Assets/Content/Fonts/example.t2font: セルのインク境界 (0, -0.25, 1, 0.8) からはみ出す字が 5 字あります（切って収めると縁が欠けるので止めます）。箱を広げるか、その字を文字セットから外してください: $(U+0024 (0.055, -0.085, 0.51, 0.815)) _(U+005F (-0.002, -0.14, 0.565, -0.08)) `(U+0060 (0.015, 0.557, 0.232, 0.81)) j(U+006A (-0.01, -0.22, 0.24, 0.75)) |(U+007C (0.135, -0.22, 0.208, 0.81))

直し方: 文面の各字の後ろの 4 つの数がその字のインク境界なので、全部を覆うまで箱を広げるか、その字を文字セットから外す。

セルが 1 つもページに入らない

"representation": { "kind": "sdf", "emPx": 256, "maxPageSize": 64 }
Assets/Content/Fonts/example.t2font: セル（316×368 px）がページの最大寸法（64×64 px）に 1 つも入りません。

直し方: maxPageSize を上げるか、emPx を下げる。

8.6元フォント

元フォントの誤りは、ベイク仕様の行番号を持たない。文面は「ベイク仕様のパス: 元フォント source を読めません: 」に続けて理由を言う。

原因理由の文面直し方
フォントコレクション（.ttc）フォントコレクション（TTC）は未対応です。単体のフォント（.ttf）を指定してください（ベイク仕様は書体の番号を持ちません）。コレクションから単体の .ttf を取り出す
CFF 輪郭のフォント（.otf の多く）CFF 輪郭（OTTO）のフォントは未対応です。TrueType 輪郭（glyf）のフォントを使ってください。同じ書体の TrueType 輪郭の版を使う
Unicode の cmap が無い・表が壊れているその表を名指す別の版のフォントを使う

元フォントのファイルが無いときは「元フォント source がありません。」になる。source の綴りとファイルの置き場を確かめる。

9再インポート

Unity は、次のどれかが変わるとベイク仕様を再インポートする（README §7.5）。

  • ベイク仕様の本文。コメントだけを直しても再インポートされる——アセットの sourceHash は、生成のバージョンと表現の種類・ベイク仕様の本文・元フォントのバイト列から作る SHA-256 で、本文をそのまま含むため。
  • 元フォントのファイル。
  • 表現のシェーダ（SDF なら T2Font/SDF）。
  • パッケージの更新で、タイポグラフィテーブルの生成のバージョンか、表現の種類のバージョンが上がったとき。表現の種類のバージョンは、その種類のフォントだけを再インポートさせる。

Project ウィンドウでベイク仕様を右クリック → Reimport でも、いつでもやり直せる。

11付録の作り方

本書の数・誤りの文面・付録の文字リストは、Tools/docs-figures/04-bake-spec/ のスクリプトが作り、本書の <!-- gen:名前 --> と <!-- /gen --> の間を書き換える（使い方は同じフォルダの README）。地の文は本書を直接直す。

  • パッケージの Core/ と Bake/ のソースをそのままリンクした .NET 8 のコンソールプログラムが、文字セットを FontCharsets.Build で組み、JIS X 0208 と CP932 の周辺の表を表の並びのまま書き出す。文字セットを変えれば、付録も作り直せば合う。
  • 誤りの文面は、基本の形を書き換えたベイク仕様を、インポーターと同じ FontBakeSpec.Parse → FontSpecBaker.BuildFace → SdfAtlasBaker.Bake に通して得た。元フォントの読み取りの文面は TrueTypeFont の文面。BC4 とターゲット・元フォントが無いとき・シェーダの文面は Unity の中でしか出ないので、本書は言葉で説明した。
  • 見本のインポートの報告は、インポーターの報告と同じ値を同じ並びで組んだもの。emPx ごとの寸法の表は、ベイクの前半（セルとページの寸法を決める所まで）と同じ計算で、見本ではベイクの結果と一致することを確かめている。
  • JIS X 0208 の区は、表の字を Python の euc_jp（JIS の標準の対応）で符号化して求め、表が区点の順であることも確かめる。WindowsVariants の JIS の側の字は、CP932 のバイト列を shift_jis で読み戻したもの。
  • 空白・未割り当ての判定は .NET 8 の CharUnicodeInfo（Unicode の一般カテゴリ）。
