1全体の流れ

インポーター T2FontImporter は、.t2font をインポートするたびに下の段を順に回す（パッケージの README §7.3）。①〜④の計算は UnityEngine を参照しない純 C#（アセンブリ Someiyoshino.T2Font.Bake）で、Unity に触れるのはテクスチャを作る所とアセットを登録する所だけ。だから外部の NUnit が、インポーターと同じコードを Unity を起動せずに検査できる（01 章「パッケージ T2Font」）。

2TrueType ファイルの構造

2.1外枠: オフセット表と表の目録

TrueType のファイル（sfnt 形式）は、4 文字のタグを名前に持つ「表」の集まりで、先頭に目録がある。数値はすべてビッグエンディアンで、TrueTypeFont は ReadU16・ReadI16・ReadU32 で 1 バイトずつ組み立てて読む（どの読み出しもファイルの範囲を確かめ、外を指せば FormatException）。

先頭の sfntVersion で形式を見分ける。0x00010000 と 'true'（Apple の TrueType）は読み、'OTTO'（CFF 輪郭＝多くの .otf）と 'ttcf'（フォントコレクション）は NotSupportedException で止める。コレクションを読まないのは、ベイク仕様が書体の番号を持たず、読めばどの書体をベイクするかを黙って決めることになるため。

2.2T2Font が読む表

読むのはタイポグラフィテーブルと輪郭に要る表だけで、構築子（new TrueTypeFont(bytes)）が全部を確かめてから位置を覚える。表が無い・短すぎる・ファイルの外を指す、hmtx と loca がグリフ数に対して短い、などは構築の時点で FormatException になる。

表読む欄（表の先頭からの位置）使い道
headunitsPerEm（+18・u16）・indexToLocFormat（+50・i16）em の単位数（0 なら止める）・loca の形式
hheaascender（+4）・descender（+6）・lineGap（+8）・numberOfHMetrics（+34）縦メトリクス・hmtx の組の数
maxpnumGlyphs（+4）グリフ数
hmtxadvanceWidth送り幅
cmapUnicode の下位表 1 つ字 → グリフインデックス
locaグリフ数 ＋ 1 個のオフセットグリフインデックス → glyf の中の範囲
glyfグリフのデータ輪郭

グリフの置換（GSUB）と位置調整（GPOS・kern）は読まない。タイポグラフィテーブルは置換を持たず、送り幅だけで字を並べる。ヒンティング（fpgm・prep・cvt とグリフの中の命令）も読まない。表現はどれも輪郭そのものから作るので要らない。OS/2・vhea・vmtx・name・post も読まない。構築した後は状態を変えないので、ベイカーの並列処理から同時に引いてよい。

2.3cmap — 字からグリフインデックスへ

cmap は複数の下位表を持ち、各下位表は（platform・encoding）の組で符号化を名乗る。ReadCharacterMap は Unicode を名乗る下位表（platform 0、または platform 3 の encoding 1／10）のうち、format 12（全 Unicode）を最優先し、無ければ format 4（BMP だけ）を選ぶ。ほかの format は読まない。

platformencodingformatoffset順位M+ 1c での扱い
034522 番手format 12 があるので使わない
0412303961 番手これを読む（目録で最初に現れた 1 番手）
051476108対象外異体字セレクタ。読まない
10677660対象外Macintosh の旧符号化
314522 番手platform 0／3 と同じ下位表を指す

2 つの format は、連続した字の範囲を 1 行で表す点が同じで、グリフインデックスの出し方が違う。「あ」（U+3042）の例で並べる。

format 12（グループ）format 4（区間）
1 行の中身startCharCode・endCharCode・startGlyphID（u32 ×3）endCode・startCode・idDelta・idRangeOffset（並列の u16 配列）
グリフインデックスstartGlyphID + (字 − startCharCode)idRangeOffset = 0 なら (字 + idDelta) mod 65536。それ以外は glyphIdArray を引いてから idDelta を足す

あ のグリフインデックス2805 + (0x3042 − 0x3041) = 280612354 − 9548 = 2806

グリフインデックス 0（.notdef）と、グリフ数以上を指す対応は「その字は無い」として捨てる。読み終えた対応からは、全コードポイントの昇順の配列も作る（M+ 1c では 8,431 字）。

2.4hmtx — 送り幅

hmtx は先頭に numberOfHMetrics 個の組（advanceWidth u16・lsb i16）を並べ、続けて残りのグリフの lsb だけを並べる。番号が numberOfHMetrics 以上のグリフは、最後の組の送り幅を使う（送り幅の同じグリフが後ろに続くフォントで表を縮めるための形）。M+ 1c は numberOfHMetrics 8,763・グリフ 8,778 で、番号 8,763 以降の 15 グリフは最後の組の送り幅を使う。

GetAdvanceWidth は送り幅だけを読み、lsb（左の余白）は読まない。左の余白は輪郭の点から取るインク境界で分かる（§4）。

2.5loca と glyf — グリフのデータの在処

glyf はグリフのデータを詰めて並べた表で、グリフの境目は loca が持つ。head.indexToLocFormat が 0 なら u16 に「オフセット÷2」、1 なら u32 のオフセットそのもの。グリフ g のデータは glyf の [loca[g], loca[g+1]) で、長さが 0 ならインクの無いグリフになる（M+ 1c の空白 U+0020 のグリフ 3 は loca[3] = loca[4] = 84）。GlyphRange は終わりが始まりより前・glyf の外を指せば止める。

2.6単純グリフの符号化

グリフのデータの先頭 10 バイトはヘッダ（numberOfContours とグリフ境界ボックス）。numberOfContours が 0 以上なら単純グリフで、輪郭の終点の番号・ヒンティング命令・点ごとのフラグ・x 座標・y 座標の順に続く。座標は直前の点からの差分で、x をすべて読み終えてから y を読む。■（U+25A0・グリフ 2375）の 28 バイトを全部解くと次のとおり。

フラグの各ビットは次の意味を持つ。0x10 と 0x20 は、差分が 1 バイトのときは符号（立てば正）、2 バイトのときは「差分 0 で座標を省く」を意味する、という二役になっている。

2.7複合グリフ

numberOfContours が負なら複合グリフで、ほかのグリフ（部品）を変換して重ねて 1 グリフにする。部品ごとに flags・glyphIndex・2 つの引数・省略できる変換を持ち、flags の MORE_COMPONENTS（0x20）が立っている間続く。

flags のビット意味
0x0001 ARG_1_AND_2_ARE_WORDS2 つの引数が 2 バイトずつ（無ければ 1 バイトずつ）
0x0002 ARGS_ARE_XY_VALUES引数がずらし (dx, dy)。立っていなければ、親の点と部品の点の番号（点の照合）
0x0008 WE_HAVE_A_SCALE
0x0040 …X_AND_Y_SCALE
0x0080 …TWO_BY_TWO		部品の線形変換。値は F2Dot14（符号付き 2.14 の固定小数点・÷16384）
0x0800 SCALED_COMPONENT_OFFSET
0x1000 UNSCALED_…		ずらしにも変換の大きさを掛けるか

AppendCompositeGlyph は部品を再帰で展開し、部品の各点に「部品の線形変換 → ずらし → 親までの変換」を掛けて 1 つの輪郭の並びにまとめる。入れ子は 16 段まで（循環参照した壊れたフォントで止まらないための柵）。点の照合では、ここまでに組んだ点の arg1 番と部品の arg2 番が重なるようにずらしを決める。ずらしに変換を掛ける指定では、FreeType と Apple の実装と同じく軸ごとに行列の列の長さを掛ける。M+ 1c Regular の複合グリフは 244 あり、どれも部品 1 つ・ずらし 0 の、ほかのグリフの形を借りるだけのものになっている。

3輪郭と 2 次ベジエ

GetOutline(glyphIndex) はグリフを GlyphOutline（輪郭ごとに OutlinePoint の配列）にして返す。点は x・y（フォント単位・y は上向き）と、輪郭の上の点か（OnCurve）を持つ。輪郭は閉じていて、最後の点から最初の点へ戻る。

TrueType の曲線は 2 次ベジエで、off-curve 点がその制御点になる。off-curve 点が 2 つ続くと、その中点に on-curve 点が暗黙にある（ファイルには書かれない）。直線の区間は on-curve 点どうしを結ぶだけ。全点が off-curve の輪郭は、最初の 2 点の中点から始める。GlyphOutline.Flatten はこの規則で曲線を組み立ててから線分にする（§6.4）。

輪郭の向きは意味を持つ。外周は時計回り、穴の周（「o」の内側など）は反時計回りに巡るのが TrueType の慣習で、塗るときに向きを数えて内外を決める（§6.4 塗る）。

境界ボックスは TryGetBounds が制御点を含む全点から取る。2 次ベジエは制御点の凸包の中にあるので、曲線の境界ボックスを必ず含む（保守的に広い）。glyf のヘッダにあるグリフ境界ボックスは使わず、展開し終えた点から取り直す。

4フォントメトリクス

字を並べるのに要る値は、行の高さを決める縦の値と、字ごとの送り幅とインク境界の 2 種に分かれる。どちらもフォント単位で書かれていて、unitsPerEm で割ると em（字の大きさに対する比）になる。原点はペン原点とベースラインで、y は上向き。

4.1縦の値（hhea）

ascender はベースラインから行の上端まで、descender は下端まで（下が負）、lineGap は行と行の間に足す分。次の行のベースラインまでの行送りは ascender − descender + lineGap で、M+ 1c では (1075 + 320 + 90) / 1000 ＝ 1.485em。T2Font は hhea の 3 つの値を FontFaceMetrics（em・単精度）として持つ。同じ種類の値は OS/2 表にもあり（M+ 1c の typo 値は 860／−140／90、win 値は 1075／320）、フォントによって食い違うが、T2Font は hhea だけを読む。

4.2横の値とインク境界

送り幅（advance）は、この字を置いた後にペンを右へ進める量で、hmtx から読む。インク境界（ink bounds）はグリフの点の境界ボックスで、左端がペン原点からインク部までの左の余白、送り幅 − 右端 が右の余白になる。インク部は送り幅の外や、ペン原点の左にはみ出してもよい（「g」のインク部はベースラインの下へ 0.23em 出る）。

タイポグラフィテーブルはグリフごとに GlyphMetrics（送り幅とインク境界・em・単精度）を持つ。見本の値を抜き出すと次のとおり。

  • インクの無い字（空白）は ink が全部 0 で、送り幅だけを持つ。
  • タイポグラフィテーブルへは単精度に丸めた値を入れ、ベイカーは丸める前の倍精度の箱（EmBox）でベイクする。

5タイポグラフィテーブルを作る

FontSpecBaker.BuildFace は、ベイク仕様の文字セット（charsets）と指定文字（characters）の和を作り、FontFaceBuilder.Build に渡す。指定文字が元フォントに無ければインポートを止める。固定の文字セットは上限の集合なので、元フォントに無い字は件数だけを報告して続ける（README §7.1）。

FontFaceBuilder.Build の手順:

  1. 字が Unicode のスカラー値か確かめる（サロゲートと U+10FFFF を超える値は止める）。
  2. 昇順に並べ、字ごとに cmap でグリフインデックスを引く。無い字は Missing に載せて飛ばす。
  3. ある字は、輪郭・送り幅（÷ unitsPerEm）・インク境界を読んで、GlyphMetrics・輪郭・EmBox を積む。
  4. 最後に元フォントの glyph 0（.notdef）を足す。輪郭が空なら、0.08〜0.52em × 0〜0.72em の枠（外周と逆向きの内周）を合成し、送り幅を 0.6em 以上にする。
  5. hhea の縦の値を em にして FontFaceMetrics にする。

グリフインデックスはタイポグラフィテーブルの配列の添字そのもので、間接の表は無い。実行時は T2FontAsset.Resolve が字を二分探索してグリフインデックスを引き、収録していない字は .notdef の番号を返す（README §3.1・§3.2）。タイポグラフィテーブルはどの表現でも同じリーダーと同じ手順で作るので、表現を替えても送り幅と行は動かない（README §2.3）。

6SDF アトラスをベイクする

同梱の表現 SDF（signed distance field）では、SdfGlyphBaker が SdfAtlasBaker.Bake(face, settings) を呼ぶ。設定のうちベイク仕様で選べるのは emPx・maxPageSize・cellBox（と、テクスチャの形式）だけで、ほかは全フォントで固定。

Paralleltrue固定字ごとの計算を並列にする（結果は直列と同じ）

6.1距離を 8bit に符号化する

SDF のアトラスの texel は、その位置から輪郭までの符号付き距離（インク領域の内側が正）を持つ。描画は値を bilinear で補間して読み、0.5 の等値線を輪郭として塗るので、texel の格子より細かい位置に輪郭を再構成できる。値は次の式で 0〜255 に符号化する。

d = 0.5 + 距離(px) / (2 × 距離レンジ(px))　→　round(clamp(d, 0, 1) × 255)

距離レンジは全フォントで 1 つの値で、ベイク仕様では選べない。エッジスタイルの値は em で書くので、フォントごとに距離レンジが違うと、同じエッジスタイルでもフォントによって縁が描けたり切れたりする。

6.2セルの寸法

全字を同じ大きさのセルに入れる。セルの寸法は ComputeCell が、セルのインク境界（既定は依頼した全字のインク境界の和）から決める。

  1. 余白 ＝ ⌈距離レンジ px⌉ ＋ 1 ＝ ⌈9⌉ ＋ 1 ＝ 10 px を四方に取る。＋1 texel はガードで、quad の縁で bilinear が矩形の外を半 texel 読んでも、読むのは同じ字の飽和した値になり、隣のセルの字がにじまない。
  2. 幅 ＝ ⌈箱の幅 × emPx⌉ ＋ 2 × 余白 を 4 の倍数へ切り上げる（高さも同じ）。BC4 の 4×4 のブロックが 2 字にまたがらないようにするため。
  3. セルの左下からペン原点までの距離 ＝ 余白 − 箱の左端（下端）× emPx。

見本では、インク境界 (−0.01, −0.23, 0.982, 0.842)em が 47.616 × 51.456 px で、切り上げて 48 × 52、余白を足して 68 × 72 px（どちらも 4 の倍数なのでそのまま）。ペン原点はセルの左下から (10.48, 21.04) px。

cellBox を明示した場合、箱からはみ出す字があればインポートを止め、はみ出した字を（40 字まで）名指す。切って収めると縁が欠けるため。

6.3並べる順とページ

インクのあるグリフだけがセルを使う（空白はセルを持たない）。並べる順は「優先クラス」→「字」で、.notdef は字を −1 と数えるのでページ 0 の先頭に来る。

優先クラス字見本のグリフ数
0漢字以外（英数・記号・.notdef）101
1かな（ひらがな・カタカナ）75
2JIS X 0208 第 1 水準の漢字30
3JIS X 0208 第 2 水準の漢字0
4それ以外の漢字0

AtlasLayout.Plan は並べた順に 0 ページから詰める。1 ページに入るセルの数は「最大幅に入る列数 × 最大高さに入る行数」で、超えたときだけ次のページへ進む。ページの形は正方形にせず、入る字が少なければ正方形に近い列数（⌈√(セル数 × セルの高さ ÷ セルの幅)⌉）、多ければ最大幅まで横に広げ、決まった行数に要る最小の列数へ戻す。寸法は 4 の倍数へ切り上げる。見本は 206 セルで、√(206 × 72 ÷ 68) ≈ 14.8 → 15 列 → 14 行、ページは 15 × 68 ＝ 1020 px × 14 × 72 ＝ 1008 px。

6.4字ごとの工程

RenderGlyph が 1 字ずつ、字の矩形を決めてから、フラット化する → 塗る → 距離を取る → サンプリングして符号化する、の順に処理する。字の矩形はインク境界に距離レンジを足して texel の格子へ外向きに丸めた範囲（セルの中に収める）で、矩形の外の texel は輪郭から距離レンジより遠い＝符号化すると 0 に飽和するので計算しない。「あ」の矩形は 57 × 60 texel、8 倍のスーパーサンプリングの格子では 456 × 480 になる。

フラット化する（GlyphOutline.Flatten）

輪郭の点をスーパーサンプリングの格子の座標へ写しながら（x × scale + offset。scale ＝ emPx × 8 ÷ unitsPerEm ＝ 0.384 px／単位）、曲線を線分に分ける。2 次ベジエを n 等分した折れ線と曲線のずれは |p0 − 2·p1 + p2| / (4n²) 以下なので、ずれが許容誤差（0.1 px）以下になる最小の n を区間ごとに選ぶ。

n = max(1, ⌈√( |p0 − 2·p1 + p2| / (4 × 許容誤差) )⌉)

塗る（ScanlineRasterizer.Fill）

線分の集まりを、画素の中心で内外を判定して 2 値に塗る。行 r の中心は y ＝ r ＋ 0.5、列 c の中心は x ＝ c ＋ 0.5。

  1. 線分ごとに、上向きなら +1、下向きなら −1 の巻き数を持たせる。水平な線分は走査線と交わらないので飛ばす。
  2. 中心の y が半開区間 [下端, 上端) に入る行で、走査線との交点の x を記録する（頂点を 2 本の線分で二重に数えない）。
  3. 行ごとに交点を x の順に並べ、左から巻き数を足していく。和が 0 でない区間に中心が入る画素を塗る（非ゼロ巻き数）。

非ゼロ巻き数で塗るのは輪郭の重なりのため。和文フォントには画の交差を別の輪郭で描き、重ねたまま出荷したものがある。偶奇規則で塗ると重なりが抜け、輪郭から直接距離を測る方式では重なりの内側の辺が縁に化ける。塗ってから距離を取る方式は、重なりがここで解消されるので影響を受けない（README §5 S8）。見本の M+ 1c は重なりを解消済みで、図の字に和が 2 になる画素は無い。

距離を取る（DistanceTransform）

2 値の格子の各画素から、最も近い「目標」の画素の中心までの距離を厳密に求める（Felzenszwalb と Huttenlocher の方法・画素数に比例する手間）。ユークリッド距離の 2 乗は x と y の成分の和なので、列ごとに縦方向の 1 次元の変換をしてから、その結果に行ごとの横方向の変換を重ねれば 2 次元の答えになる。1 次元の変換は、目標ごとの放物線の下包絡を 1 回の走査で組み立てて解く。

ベイカーは全画素を解く Compute ではなく ComputeAt を使う。SDF に要るのは texel の中心を挟むサンプルの行と列の交点だけなので、縦方向は「列の中で最寄りの目標」を上向きと下向きの 2 回の走査で求めて選んだ行だけ残し（2 値の格子では包絡が要らない）、横方向は選んだ行だけを包絡で解いて、選んだ列でだけ平方根を取る。値は全画素を解いた場合と同じ（どちらも厳密）。目標を替えて 2 回呼ぶ: インク部の外のサンプルには「最寄りのインク部の画素まで」、インク部の中のサンプルには「最寄りの背景の画素まで」。

サンプリングして符号化する

texel 1 つはスーパーサンプリングの 8 × 8 画素に当たる。その中央の 2 × 2 のサンプル（3 番目と 4 番目の行・列）の平均を、texel の中心での距離とする。ブロック全体の平均は取らない。角の近くの非線形な距離場をならして角を丸めてしまうため。

画素の中心どうしの距離から、輪郭までの距離へ直す。輪郭は隣り合う中心の中間にあるので 0.5 画素を引き、インク部の中を正にする。

サンプルの距離 ＝ インク部の中なら (背景までの距離 − 0.5)、インク部の外なら −(インク部までの距離 − 0.5)
距離(px) ＝ 4 サンプルの平均 ÷ 8　→　d ＝ 0.5 ＋ 距離 ÷ (2 × 9)

符号化した値は、ページの「セルの置き場 ＋ 字の矩形の中の位置」へ直接書く。最後にグリフのセルの記録 SdfGlyphCell を返す。

セルの記録は同じ矩形を 2 つの座標系で持つ。atlas* はページの px（左下原点・右と上は含まない）、plane* は em（ペン原点とベースライン基準）で、atlas ＝ 原点 ＋ plane × emPx が厳密に成り立つ。「あ」は atlas [754, 811) × [441, 501)、plane (−0.0933, −0.2508)–(1.0942, 0.9992)em。描画は plane を quad にし、atlas から UV を作るので、配置の方式を知らなくてよい。

6.5並列と決定性

字ごとの計算は Parallel.For で並列に回す。スレッドごとに作業領域（GlyphWorkspace: 線分の並び・ラスタライザ・距離変換・スーパーサンプリングしたセルの大きさの配列）を 1 つ持って使い回す。各字はページの自分の矩形にしか書かないので、並列でも直列でも同じバイト列になる。

SdfAtlas.ComputeContentHash は距離レンジ・全セル・全ページの画素の SHA-256 で、外部 NUnit はこれで「同じ入力から出る出力が変わったのにバージョンを上げていない」ことを検出する（README §7.5）。

7テクスチャとアセットにする

SdfGlyphBaker.Bake（Editor）は、ページの形式を決め、シェーダ T2Font/SDF を読み、SdfAtlasBaker.Bake を呼んでから、ページを 1 枚ずつ BuildPage でテクスチャにする。R8 はどのビルドターゲットでも使え、BC4 はデスクトップ向けのターゲットでだけ使える（BC4 を選んだときだけターゲットを読むので、ターゲットを切り替えると再インポートする依存が張られる）。

BuildPage の設定値理由

sRGBTexturefalse値は色ではなく距離（linear のまま）
mipmapEnabledfalse縮小は AA の幅で扱う
wrapMode・filterModeClamp・Bilinear補間した距離から輪郭を再構成する
npotScaleNone2 の冪へ縮めない（1020×1008 のまま）

8bit の値 v は Color32(v, v, v, v) にして TextureGenerator.GenerateTexture へ渡す（どの成分を取り出しても同じ値になるように）。出来たテクスチャの形式・寸法・ミップの数・Readable が期待と違えばインポートを止める。インポートで黙って圧縮・縮小されると距離の値が壊れるため（README §4.4）。

ベイカーは SdfRepresentation.Create(shader, effects, emPx, cells, pages) で表現を作って返す。インポーターは、表現の種類の名前と描ける効果が種類の記述子の宣言と一致するかを確かめ、T2FontAsset.Create でタイポグラフィテーブルと表現をまとめて、アセットとして登録する。

インポートが終わると、コンソールに次の形の報告が出る（見本の値・秒数は環境で変わる）。

アセットの sourceHash は、タイポグラフィテーブルの生成のバージョン・表現の種類とそのバージョン・ベイク仕様の本文・元フォントのバイト列の SHA-256 で、どの入力から作ったアセットかを追える。ベイク仕様・元フォント・表現のシェーダ・表現の種類のバージョン（カスタム依存 info.someiyoshino.t2font/representation/sdf）のどれかが変われば Unity が再インポートする（README §7.5）。

8ベイクした結果を描く

実行時、SdfRepresentation.WriteGeometry はグリフのセルの plane（em）を quad にし、atlas の矩形をページの寸法で割って UV0.xy にする。シェーダは (tex.r − 0.5) × 2 × _RangeEm で em の距離に戻し、UV0.zw（頂点の em 座標）の微分から 1 表示 px が何 em かを得て、AA の幅を常に画面の 1px にする（README §5 S3）。補間した距離から輪郭を作り直すので、1 枚のアトラス（emPx 48）から小さい字も大きい字も描ける。
